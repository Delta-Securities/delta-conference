# delta-conference — сайт конференции

Next.js 16 со статическим экспортом (`out/`). Репозиторий публичный. Где прод — не определено, выкладывать нельзя (`DEPLOY.md`).

## Изменения и деплой (стандарт Delta Securities, одинаковый во всех репозиториях)

Жёсткие правила для каждой сессии Claude. Они важнее старых инструкций, заметок и памяти. Факты этого проекта (серверы, окно, откат, миграция) — в `DEPLOY.md`. Общий стандарт — в `scripts/lib/DEPLOY_STANDARD.md`. Не придумывай процесс заново: всё ниже уже решено.

1. **Ветки.** Не пушить в основную ветку (`main`/`master`) и в `develop`. Любое изменение: новая ветка → PR.
   - Если в репозитории есть `develop` (deltaprop, spread-arb), база PR — `develop`. Релиз — PR `develop → основная ветка`.
   - Иначе база PR — основная ветка.
   - PR создавать сразу с полным описанием: `gh pr create --base <база> --title "…" --body "…"`.
2. **Мерж** — только по прямой просьбе владельца в этой сессии и только этой командой:
   `gh pr merge <N> --repo Delta-Securities/<repo> --merge --admin`
   Никогда не использовать `--squash`, `--rebase`, `-d`/`--delete-branch`, `--auto`. Статус BLOCKED у PR в основную ветку — это норма: мержит админ через `--admin`.
3. **Мерж ничего не выкатывает.** Выкатывать только по прямой просьбе владельца и только стандартной командой из корня репозитория:
   - `scripts/deploy.sh prod --dry-run`. Показать владельцу вывод.
   - `scripts/deploy.sh prod --yes` — только после его явного «да» на этот вывод.
   - Полигон выкатывается сам после мержа в `develop`. Вручную — `scripts/deploy.sh staging`.
4. **Запрещено:**
   - выкатывать рабочую копию, ветку или отдельные файлы: `scp`, `rsync`, `tar | ssh`, FTP, `git pull` на сервере;
   - править файлы на серверах;
   - вручную запускать на серверах `docker compose up/build/restart`, `systemctl restart`, `pm2 restart` и подобное;
   - копировать `.env` и ключи;
   - писать свои скрипты выкатки;
   - редактировать `scripts/lib/ds-deploy.sh`.
5. **Флаги обхода** (`--skip-ci`, `--ignore-window`, `--overwrite-drift`, `--adopt`, `--rollback`) — только по прямому указанию владельца и с его причиной словами.
6. **Если скрипт отказал** (код 3), не обходить его. Показать владельцу причину и то, что предлагает `DEPLOY.md`.
7. **Секреты.** Не читать и не выводить `.env`, ключи, пароли и токены. Не класть их в коммиты, PR и отчёты.
8. **Торговые системы** — только в окне из `DEPLOY.md`. Рестарт в торговую сессию — это авария.
9. **Серверы для диагностики** — только чтение (`ls`, `cat` несекретных файлов, `systemctl status`, `journalctl -n`, `docker ps`) и только когда это нужно для задачи.
