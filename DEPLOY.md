## Изменения, мерж

1. Ветка `<тип>/<кратко>` от `master`, затем PR в `master`. Прямой push в `master` запрещён.
2. CI (`.github/workflows/ci.yml`, проверка `ci`: shellcheck, сверка библиотеки деплоя, `npm ci`, `npm run lint`, `npm run build`) должен быть зелёным.
3. Мержит владелец:
   `gh pr merge <N> --repo Delta-Securities/delta-conference --merge --admin`
   Claude не мержит (запрещено в настройках владельца) — готовит эту команду с номером PR.
4. Мерж ничего не публикует: автопубликации по push нет (Netlify/Vercel к репозиторию не подключены, вебхуков нет — проверено 24.09.2026).

## Где прод

Не найден (24.09.2026). Раньше сайт публиковался вручную командой `netlify deploy` из рабочей копии на ПК (по сгенерированному локальному конфигу Netlify CLI, предположение). Адрес `delta-conference.netlify.app` принадлежит чужому сайту. Конференция прошла в апреле 2026 (предположение по содержимому).

До решения владельца выкладывать сайт куда-либо нельзя — ни `netlify deploy`, ни вручную.

Что решает владелец:
1. Нужен ли сайт дальше. Если нет — пометить проект закрытым (как Vertex) и при желании архивировать репозиторий.
2. Если нужен — где хостить. Варианты по стандарту:
   - статика `out/` на сервере компании: `scripts/deploy.sh` по шаблону стандарта, цель со сборкой из архива коммита (`ds_site_build() { npm ci && npm run build; }`, `DS_BUILD_OUT=out`, `DS_ADOPT_MODE=replace`);
   - Netlify: только через `scripts/deploy.sh` (в библиотеке пока нет такого транспорта — нужна новая версия), без ручного `netlify deploy`.
3. Какая локальная копия — истина. Есть две расходящиеся копии одной работы (press-wall и др.): одна с незакоммиченными файлами, другая с неотправленным коммитом. Их нужно свести в одну ветку и открыть PR в `master` (делает владелец или Claude по его просьбе).
